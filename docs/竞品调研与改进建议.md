# 竞品调研与改进建议

> 调研时间：2026-10-15 ｜ 对照对象：本工具 v1.4.0
> 方法：只采信能读到源码或 README 明确功能表的开源项目；每条建议都标了来源与「改动量」，
> 并核对过本机 Telethon 1.45 里对应 API 是否真的存在（避免建议里塞进做不到的事）。

## 一、调研对象

| 项目 | 形态 | 与我们重叠的部分 | 值得我们抄的点 |
|---|---|---|---|

| [amrulizwan/tele-out](https://git.bytes.zone/amrulizwan/tele-out) | CLI | 逐个确认退出（ENTER/ESC） | 「一个会话一次确认」的交互（我们已有等价能力：勾选 + 确认清单） |
| [pardhasaradhi96/telegram-restricted-channel-cleaner](https://github.com/pardhasaradhi96/telegram-restricted-channel-cleaner) | 脚本 | 检测因版权被封的频道 | 已并入 v1.4.0 的异常筛选（且我们做了代码优先/文案兜底） |

**一句话结论**：竞品里**没有一家在「删/退之后回头向服务端复核」**，也**没有退出历史/撤销**；
我们的「不谎报成功 + 异常特征来自服务端字段」这两条是实打实的领先项。
差距集中在**可视化、可恢复性、账号安全面、以及把「清理」做成可重复的方案**。

## 三、建议清单

### P0 — 小改动，直接补上定位缺口（建议打进 v1.5.0）

**1. 订阅配额指示（500 / 1000）** ｜ 来源：本工具定位 + Telegram-Panel 统计面板 ｜ 改动量：小
- 动因：README 写着「解决订阅满 500 加不进去的问题」，但界面上**看不到自己用了多少**。
  在「这次退出能腾出几个名额」上，用户现在只能心里估。
- 改法：连上账号后读 `me.premium`（Premium → 1000，否则 500）；已用 = 当前列表里
  频道 + 群组数（零请求，自己数）；统计条改为
  `📢 447 / 500 名额（剩 53）`，批量退出过程中实时递减，结束时报「本次腾出 40 个名额」。
- 风险：**上限是客户端本地知识、不是服务端返回的**，所以文案要写「按免费账号 500 / Premium 1000
  估算」，不能说得像服务端权威值。

**2. 退出历史 + 一键重新加入（撤销）** ｜ 来源：无竞品有（差异化） ｜ 改动量：中
- 动因：退出是**不可逆**操作，现在唯一的后悔药是自己提前记住链接。
- 改法：退出/删除前把 `(id, username, title, 类型, 时间)` 落到 `tg_history_<账号>.json`（本地，
  不含敏感信息）；新增「🕘 退出历史 ▾」：查看 / 复制链接 / **重新加入选中的**
  （公开频道用 `channels.JoinChannelRequest(username)`，邀请链接用
  `messages.ImportChatInviteRequest(hash)`，加入前用 `CheckChatInviteRequest` 预检）。
- 风险：私有且无链接的频道无法重新加入 —— 这种情况在历史里明确标「不可重加」，不假装能救。
- **API 已核对**：三个接口在 Telethon 1.45 中都存在。

**3. 「空会话 / 僵尸会话」筛选预设** ｜ 来源：chat-manager 的「No Messages」分类 ｜ 改动量：小
- 改法：预设下拉加「空会话（作品数 = 0）」「无消息私聊」，复用已有阈值筛选机制。
- 设计纪律：**这类是我们*推断*的，不塞进「异常」列** —— 异常列只放服务端标记
  （封禁/违规/诈骗…），推断类走筛选。两类混在一起会让人不信异常列。

**4. 日志面板升级：级别过滤 + 搜索 + 一键复制 + 自动滚动开关** ｜ 来源：Telegram-Panel「日志降噪」、TG Manager 彩色日志 ｜ 改动量：中
- 现状：长任务刷屏（一轮 60 个会话就是上百行），想找某一行的失败原因只能翻。
- 改法：日志行带级别（info/warn/error），面板上方一排复选框 + 搜索框 + 「复制全部」；
  末尾「跳到底部」开关（现在强制滚动，用户手动上翻时会被拉回去）。

**5. 三个小件（成本极低、观感提升明显）**
- **工具提示**：给按钮/列头加 tooltip（Tk 用 `after` + `Toplevel` 30 行即可）；
- **F1 快捷键面板**：把现有快捷键（Ctrl+F/A/G、空格、F5、Esc）集中显示；
- **首次使用引导**：未连接时表格区显示引导卡片（三步：填 API → 登录 → 刷新），而不是空白表格。

### P1 — 中等成本，体验跃升（建议 v1.6.0）

**6. 暗色主题补完整**（✅ v1.6.0 已做）｜ 来源：chat-manager 暗色玻璃拟态、TgGod 深浅切换 ｜ 改动量：中
- **勘误**：本报告初稿写「没有暗色主题」，是我看漏了 —— 实际早有「外观 → 深色模式」开关。
  真正的缺口是**它没做透**：行 tag（白名单 / 创建者 / 异常分级）与日志级别颜色是硬编码的浅色，
  说明标签也写死了浅灰，深色下糊成一片。
- 改法（已实现）：抽 `THEME_LIGHT / THEME_DARK` 调色板 → `ttk.Style`（clam）统一 Treeview/Notebook/
  Button + 行 tag 配色（斑马纹只给背景、保护与异常只给前景，两组不打架）+ 日志级别颜色随主题提亮 +
  **遍历控件树**把写死浅灰的说明标签统一换色；**不加新依赖**。
- **不做「跟随系统」**：那要读注册表（`AppsUseLightTheme`），本项目不碰注册表，只给浅色 / 深色两个明确选项。

**7. 数据可视化（Canvas，零依赖）** ｜ 来源：Telegram-Panel 数据面板 ｜ 改动量：中
- 「统计」页加：类型分布环形图、用户数量级分布（<100 / 100–1k / 1k–10k / >10k）、
  活跃度直方图、异常类别条形图。全部用 `tk.Canvas` 画静态矢量，不需要 matplotlib。
- 价值：636 个会话现在是「一堆数字」，一眼看不出「我这 447 个频道里有多少是 200 人的僵尸群」。

**8. 任务可恢复 + ETA + 速率** ｜ 来源：TG Manager 的 auto-resume / Telegram-Panel 任务配置 ｜ 改动量：中
- 改法：批量操作每完成一个就写 `tg_task_<账号>.json`（已完成 id）；启动时若发现未完成任务，
  提示「上次退出 60 个只完成 23 个，是否继续剩余 37 个」；进度条上叠加
  `127/447 · 剩余约 4 分 · 1.2 个/秒`；把「间隔 / 抖动 / 最大并发 / 限流自动等待」做成可保存的配置。

**9. 登录设备管理（踢出其他设备）** ｜ 来源：Telegram-Panel「批量踢出其他设备」 ｜ 改动量：中
- 改法：新「设备」页，`account.getAuthorizations` 列出（设备 / 系统 / IP / 国家 / 最近活跃 / 是否本机），
  勾选后 `account.resetAuthorization(hash)` 踢出。**只操作自己账号的设备**，天然安全。
- 价值：这是账号安全的高频需求，且完全落在「管理自己的账号」这条线内。
- **API 已核对**：两个接口都在。

**10. 会话快照与对比（diff）** ｜ 来源：无竞品（差异化） ｜ 改动量：中
- 改法：导出 JSON 快照（id/名称/类型/用户数/作品数/时间/异常码）；下次「与上次快照对比」输出
  「新增 12 / 消失 5 / 改名 3 / 用户数变化 8 / 新增异常 2」。
- 价值：把「一次性清理」变成「长期维护」，也顺势补上 JSON 导出。

**11. 批量静音 / 归档（不退出）** ｜ 来源：我们自己的菜单结构（退出/删除之间缺一档） ｜ 改动量：小
- 改法：右键菜单与删除菜单加「🔕 静音」`account.updateNotifySettings(InputNotifyPeer, mute_until)`
  与「📦 归档」`folders.editPeerFolders([InputFolderPeer(peer, folder_id=1)])`。
- 价值：给「太吵但不想退」的会话一个中间选项，减少不可逆操作。
- **API 已核对**：都在。

### P2 — 大功能 / 可选（v1.7.0 或按需）

**12. 自动化清理方案 + 无人值守** ｜ 来源：Telegram-Panel 定时任务、orca-fleet 批处理
- 把「筛选条件 + 动作 + 间隔 + 白名单」存成**方案**（`tg_plans_<账号>.json`），
  提供 `--auto-plan "每周清一次"` 无界面执行（配 Windows 计划任务即可），日志仍落盘。
- 我们已有 `--selftest` 这类命令行入口，加一个 `--auto-plan` 是顺路的。

**13. 英文界面（i18n）** ｜ 来源：TgGod / TG Manager ｜ 改动量：中
- 文案集中成 `STRINGS = {"zh": {...}, "en": {...}}`，界面切换 + 配置持久化。开源受众面能大一截。

**14. 表格大数据量虚拟化** ｜ 现状：636 行流畅；5000+ 行才需要。暂不做。

**15. 导出 JSON / Excel** ｜ JSON 十行代码（配合快照）；xlsx 要加 openpyxl，暂不做。

## 四、UI / UX 专项建议

**信息层级**
- 现在「筛选」「选择」「操作」「危险操作」四排按钮视觉权重相同，长任务里容易点错。
  建议：筛选=浅灰次要；选择=中性；**退出/删除=红色系**（`#c0392b` 已在验证码提示里用过），
  并且把「🚪 退出 / 🗑 删除」固定到列表底部右侧（现在在左下，视线要来回跳）。

**表格可读性（成本低、收益最直观）**
- **斑马纹** + 行高 24px；`选择`列居中固定宽度；
- **类型列图标化**：📢 频道 / 👥 群组 / 💬 私聊 / 🤖 机器人 / 🚫 已不在（统计条已有图标，表格里没有）；
- **数字右对齐 + 千分位**：`32,519` 比 `32519` 好读太多（现在都是左对齐裸数字）；
- **空值统一**：现在三种符号混用 —— `-`（不适用）、`…`（未获取）、`无消息`。建议统一为
  「`—` 不适用」「`…` 加载中」「明确文案留给真实结果」，并在图例里说明；
- **异常列着色**：封禁/违规用红、禁言/需审核用橙、已注销用灰，一眼分出轻重；
- 双击列分隔线自动列宽（`tree.column(c, width=...)` + 测量文本长度实现，不需依赖）。

**反馈方式**
- 把「已导出 128 条」「已复制 ID」这类**成功提示从 messagebox 换成右下角 toast**
  （1.8 秒自动消失）—— messagebox 每次都要点「确定」，批量操作里非常打断；
  真正的**危险确认**才用模态框（保持现在的确认清单）。
- 进度条上叠字：`127/447 · 剩余约 4 分 · 1.2 个/秒`（现在是独立小字，眼睛要两边找）。

**危险操作的心理安全感**
- 确认窗里已经有「会失去什么」的清单（好），建议再加一行**「这次操作不可撤销；可从『退出历史』重新加入 N 个公开频道」**
  —— 这句话能显著降低误操作的焦虑，也让「退出历史」功能被用户发现。

**一致性**
- 「退出 / 删除会话 / 销毁」三个概念现在靠文字区分，建议**颜色 + 图标固定成肌肉记忆**：
  退出=🔓 蓝、删除会话=🗑 橙、销毁=🔥 红。

## 五、明确**不建议**做的（照抄会踩红线或与定位冲突）

| 竞品功能 | 为什么不做 |
|---|---|
| 批量加群 / 批量订阅、批量邀请成员、批量发消息、群发克隆 | 这是 Telegram ToS 明确打击的**主动营销行为**，风控红线，直接指向封号。我们做的是「管理自己已有订阅」，不是增长工具。 |
| 刷粉 / 养号 / 定时发言 / 对接刷量 API（Telegram-Panel 的 TODO 里就有） | 同上，且需要引入外部灰产服务。 |
| 批量给陌生人发消息、批量拉人 | 同上。 |
| OCR / 频道内容抓取分析 | 与我们另一条项目红线一致：不做内容层抓取。 |
| 联网检查更新 / 遥测 | 「纯本地、不依赖第三方服务器」是我们的卖点，不能为了自动更新破掉。 |
| 强制云端存储规则 / 方案 | 同上；方案存本地 JSON 即可（用户可自己同步）。 |

**判断标准一句话**：只要功能是**帮用户管自己已经拥有的东西**（退、删、归档、静音、复核、备份、
撤销、设备管理）就做；任何**帮用户去影响别人 / 拉新**的功能都不做。

## 六、建议的落地顺序

| 版本 | 内容 | 理由 |
|---|---|---|
| **v1.5.0** | P0 全部（配额指示 / 退出历史+重新加入 / 空会话预设 / 日志面板 / 三小件） | 全是小改动，但直接补上「不可逆操作没有后悔药」和「看不到配额」两个真痛点 |

## 附：本次结论的一句话

**我们缺的不是「更多能做的事」，而是「让人敢做、看得懂、做得回来」**：
配额可见、危险操作可逆（退出历史）、长任务可续、结果可视化、深色主题 ——
这五件事做完，这个工具就从「一个能用的脚本」变成「一个敢长期挂着用的管理台」；
至于批量加群/群发那类竞品主力功能，**是别人的生意，不是我们的**。
